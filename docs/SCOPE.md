# 当前功能目标

首要目标是独立实现本地微信读取与归档的主要功能。代码、阶段结果和修复持续保存 Git 历史。GitHub 仓库保持私有，不安排自动公开。

## 核心闭环

1. 本机微信 4.x 数据接入：识别账号与数据目录，建立只读接入路径，验证所需密钥与格式；不修改微信源数据。
2. 消息解析与归档：统一文字、引用、系统事件和媒体消息表示，按稳定标识去重，保留已采集消息的状态变化。
3. 后台增量同步：识别新消息和更新，事务提交游标；重启后续跑，状态中展示最近成功同步时间和错误。
4. 查询：会话列表、未读状态、联系人查找、按人/群/时间/类型检索、命中前后文、长消息详情和新消息阅读位置。
5. 联系人与群：备注和昵称区分、同名消歧、群成员查询。
6. 媒体与语音：读取本地可用图片、视频和文件；语音转写独立排队，模型或媒体不可用时给出明确状态。
7. 工具交付：CLI、供 AI 使用的 Skill 入口、结构化输出、导出、自检、后台安装与运行说明。

朋友圈、收藏和转账统计作为主要闭环之后的功能批次，按实际需求与接入难度安排。网页、MCP、向量检索与 AI 问答排在主要功能之后。

## 验收原则

- 每项功能区分未实现、合成数据验证和真实本机验证；真实接入未完成时不宣称实时读取可用。
- 只有撤回前已采集的原文才可能保留；不承诺恢复此前未采集的内容。
- 查询并发不干扰同步；重复入库、中断重启、未知消息类型、媒体缺失都有明确行为。
- 当前仓库仅完成 M0 文档初始化，尚未交付以上功能代码。
